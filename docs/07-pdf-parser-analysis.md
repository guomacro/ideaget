# 07 · 学术 PDF → 结构化 JSON：选型与可行性（规则版）

目标：把一篇学术论文 PDF 整理成结构化 JSON（标题/作者/摘要/章节正文/参考文献/
图表），先**不接视觉模型**，纯规则 + 底层库实现，供后续 RAG 使用。

采用组合路线：**pdfjs-dist 为引擎 + 自研布局算法**（读取顺序/多栏）+ OPS 取
线条与图对象（规则表格/图形检测）；视觉模型（MinerU/GPT-4o/Claude）作为后续
"复杂版面 + 无框表格 + 图注"的增强层，不在本轮。

## 可行性结论

- 单栏/双栏的**阅读顺序**：规则可做到较高正确率（行带聚类 + 栏空隙切分），
  是本轮重点；公式/浮层/页眉页脚仍会有噪声。
- **图片**：可经 OPS paintXObject 抓取到图像对象字节（保真 PNG/JPEG），
  但页面坐标(bbox)与"图注配对"不稳，JSON 只给 page+索引+文件。
- **表格**：只有"有框线表格"能走规则（线段聚类→网格→单元格文本）；
  无框表格（arXiv/多数期刊排版）规则基本失效 → 诚实输出空并提示走模型层。
- 输出结构参照 Marker 子集（schema `academic-paper/v1`）。

## 设计（实现于 src/content/academic.ts）

1. 每页取文本项（含 x/y/宽/高）→ 行带聚类 → 栏空隙检测（多栏切分）→
   逐"带"按栏序拼接 → 段落（带间纵向空隙）→ 全文。
2. 章节切分：标题启发式（编号/全大写/短行）+ Abstract/References 特判；
   References 复用 extractReferences。
3. 图：OPS paintXObject → 图像对象字节落盘；表：OPS rectangle/stroke 线段
   聚类成网格 → 单元格文本（尽力而为，失败留空并注明）。
4. 合并 Zotero 元数据（标题/作者/摘要/DOI/关键词）→ 输出 JSON + 落盘
   artifact（供 RAG），并注册模型工具返回统计与路径。

## 验证方式（本轮）

选 3+ 篇真实论文跑脚本，产出 JSON artifact，人工核对：
① 语序（段落首尾、跨页衔接）② 表述流畅度（无栏交错/行内断裂）
③ 表格有无错位（框线表）④ 章节/参考文献是否归位。

## 实测补记（2026-09）：表格提取"依次尝试"结论

对本库 3 篇真实论文（LiLa-WAM / MagicAgent / IFNet）依次尝试：
1. **pdfexcavator 0.1.2**（宣称 pdfplumber 等价、边框/无框表+置信度）：
   能打开 16–36 页 PDF，但 `page.extractTables()` 在**三篇全部返回 0 张表**。
2. **线条检测**（OPS rectangle/stroke → 网格）：同样 0——这些 PDF 的表格以
   文本/无框线排版，无可用规则信号。
3. **文本对齐**（列起点聚类）：未发现稳定表状行组。

结论与可行性文档一致：**该批 PDF 的表格只能走模型层**（页面渲染 + 多模态/
MinerU），规则引擎对"无框表"如实输出 0，不做伪数据。
